NIGHTSHIFT | WINDOWS QUICK START
==============================

This is the Solana paper desk. It reads market data over the internet and
simulates trades locally. No private key, real funds, or paid API key is
required to start. Missing required evidence still blocks an entry.

1. Install Docker Desktop for Windows from the official instructions:
   https://docs.docker.com/desktop/setup/install/windows-install/
   Use its WSL 2 / Linux containers setup. If Windows asks you to enable or
   update WSL or reboot, follow the installer. Open Docker Desktop and wait
   for the engine to be running. You do not need to install Python separately.

2. Right-click Nightshift-paper-desk.zip, choose Extract All, and open the
   inner nightshift folder containing compose.yaml. Keep this folder in a
   stable location. Do not run the launcher from inside the ZIP viewer.

3. Double-click Start Nightshift.cmd. It builds the app, starts the container
   in the background, waits for its health check, and opens the dashboard.
   The first build needs internet access. This launcher does not install
   system components, request a wallet, or change your Windows power settings.

   MANUAL EQUIVALENT (also use this if you prefer not to run a .cmd file):
   In the folder containing compose.yaml, click File Explorer's address bar,
   type powershell and press Enter. In that PowerShell window run:

       docker compose up -d --build --wait

   Open http://127.0.0.1:8080 in a browser on the same PC. The default port
   is local-only on purpose; do not expose the unauthenticated UI publicly.

4. Check Paper portfolio > Execution readiness. The first scan starts
   automatically on a fresh book. Zero positions is normal until a coin clears
   every filter, the score threshold, and Risk. A fresh installation has a
   separate $10,000 PAPER balance; it does not sync with the Arena session.

OVERNIGHT
Keep the PC powered, online and awake; leave Docker Desktop running. Windows
may sleep when the laptop lid is closed even with the charger connected.
The browser and terminal may be closed. The session stops taking new entries
at the next 07:00 Kampala time (EAT); Paper portfolio and Audit log show
results. Use New session after the previous session finishes if you want
another night. Turning the PC off also stops risk monitoring.

COMMANDS (in the same folder as compose.yaml)
    docker compose ps                      Check status and published port
    docker compose logs --tail 30 nightshift  Show recent scans/errors
    docker compose stop                    Stop the desk, keep the ledger
    docker compose start                   Restart its existing container

Keep the project/folder name consistent. The ledger lives in a named Docker
volume. Do not use down -v, delete that volume, or reset Docker Desktop if
you want to keep the ledger. Use the UI Pause button rather than stopping
Docker if you only want to stop entries and continue monitoring positions.

OPTIONAL READ-ONLY PROVIDER KEY
No .env file is needed for the default installation. If you have a read-only
SolanaTracker data API key and want its extra bundle/creator coverage, copy
.env.example to .env in the same folder (only if .env does not exist). Edit
.env privately and set SOLANA_TRACKER_API_KEY. Run docker compose up -d again
to apply the change. Never enter a wallet private key or seed phrase.

TROUBLESHOOTING
- Cannot connect to Docker: open Docker Desktop and wait for its engine.
- No configuration file: open PowerShell in the folder with compose.yaml.
- WSL error: use the official installer instructions linked above; do not
  disable Windows security features to run the launcher.
- Port already in use: edit the ports line in compose.yaml from
  "127.0.0.1:8080:8080" to "127.0.0.1:8081:8080" (only change the host port).
  Start the desk again and browse to http://127.0.0.1:8081 instead.
- Readiness is fine but no trades: look in Candidate feed and Audit log for
  exact kills. A provider outage or missing launch evidence is not a pass.

For a ledger migration instead of a fresh book, see backup.py and README.md.
Do not run two copies of a checkpoint as if they were one portfolio.
